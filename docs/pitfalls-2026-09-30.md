# Dino 動態改版與正式發布踩坑

## 1. 推送成功不等於正式網站已更新

- 現象：GitHub main 已是 `0de4356`，Vercel 仍是舊 commit。
- 處理：分別核對 repo SHA、部署 meta、READY、正式 alias 與公開 HTML；最後透過 CLI 部署乾淨 commit 匯出包。
- 防再犯：repo、Actions、Pages、Vercel 各自驗證，不能只看其中一個綠燈。

## 2. Pages workflow 沒跑，不一定是失敗

- 既有 workflow 的 push paths 只含 workflow 本身與 `public/github-pages/**`。
- 網站來源或文件改動不會觸發此 workflow；本次依使用者確認手動 dispatch，run `36596278234` 成功。
- Pages 只有轉址；它的成功不是 Next.js API、Supabase 或正式表單成功的證據。

## 3. 沙箱連線錯誤可能被誤判為登入失效

- 一般環境出現 GitHub 無法連線與 gh token invalid；取得連線權限後，同一 gh 登入可用且正常 push。
- 防再犯：先分清網路／沙箱、Git credential、gh 與 GitHub App 權限，不直接刪除或重設憑證。

## 4. Vercel CLI 確實需要重新登入

- 在已允許連線的環境下，CLI whoami 仍回 token invalid。
- 取得使用者確認後啟動官方 device flow，由使用者完成授權；再確認帳號、既有 projectId／orgId 才部署。
- 不把密碼、device code 或 token 存入筆記、repo、命令歷史範本。登入後的 CLI 升級提示選擇不升級，維持本次已驗證版本。

## 5. 外掛名稱存在不等於該操作可用

- Vercel get_project 出現連接器 projectId 與後端 idOrName 不一致；deploy_to_vercel 回工具不存在。
- 列表與 deployment 查詢可用，卻不能推定寫入工具也可用。
- 改用既有 CLI，不反覆猜參數、不為發布放寬安全設定。

## 6. 不要把整個髒工作目錄直接上傳

- 開工時保留使用者的 AGENTS.md、docs/agents/；環境另外有 .env、QA 資料、.next 等本機檔案。
- 精準 stage 22 個網站／測試／驗收檔案，部署時從已推送 commit 匯出執行所需來源，再做 dry run。
- 實際上傳 69 個檔案，不含 .env 或 QA 名單；正式環境沿用既有 server-side 設定。

## 7. 表單成功 focus 不代表使用者看得到

- 手機成功標題曾在視窗上方；preventScroll 雖保住焦點，卻沒呈現結果。
- 改為進場完成後 focus＋scrollIntoView＋scroll margin；實測標題 top 約 120px，導覽列 bottom=69px。
- 成功回執仍是時段偏好，不是預約已成立。

## 8. 跑馬燈與粒子有連續性問題

- 兩份短文字在寬畫面可能不足以無縫循環：軌道至少為視窗兩倍，副本均分，寬螢幕測量確認。
- 粒子若重新從 0 計時，暫停後恢復會跳：保存累積時間，限制單幀時間差。
- 提供暫停、離屏停止與 reduced-motion 分支；未做的真機／系統偏好驗收要明確標註。

## 9. 不要把動畫中間影格當最終結果

- 點擊後立即讀取可能還是高度 0 或舊分類；過早截圖也可能出現視窗縮放或捲動中的畫面。
- 使用完成後 DOM／截圖交叉驗證；淡出內容使用 inert，避免可點擊的隱形元素。
- label 內出現驗證訊息會改變可存取名稱；回歸測試使用穩定欄位 ID。

## 10. 本機開發與正式儲存要明確隔離

- dev 模式本身不代表資料隔離；.env.local 可能仍指向正式 Supabase。
- 本機測試設定 ANALYTICS_LOCAL_ONLY=1 與獨立 ANALYTICS_DATA_DIR，且 bypass 僅 development 生效。
- EADDRINUSE 先確認既有已知服務，不任意終止他人程序；正式發布驗證不送測試客戶名單。

## 11. Obsidian 存取被拒不代表 Vault 不存在

- 取得權限後成功讀取主 Vault；再核對 Obsidian 註冊的 open vault 為 G:/我的雲端硬碟/oB。
- 只新增／追加已確認專案紀錄，保留 Clippings 與历史筆記，寫後讀回。
- 本機掛載磁碟讀回僅證明寫入，不能宣稱 Google Drive 雲端同步已完成。

## 12. 警告、測試成功與生產健康要分開

- Node MODULE_TYPELESS_PACKAGE_JSON 是現有測試載入提示，9 項測試仍通過，未為消警告改全站 module 設定。
- 遠端安裝顯示 install-scripts 提示，但 build 成功；沒有因此變更安裝政策。
- Runtime error／fatal 查不到紀錄不等於沒有任何錯誤，更不等於已有長期監控。
