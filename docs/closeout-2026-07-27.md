## 踩坑與處理方式

### 新事件已寫進程式，但資料庫約束仍是舊清單

- 症狀：Production 送出新事件時會被 `analytics_events_type_check` 拒絕。
- 原因：前端與 API 發布不會自動修改既有 Supabase CHECK constraint。
- 處理：先執行 `supabase migration list --linked`，確認 remote 缺少
  `202607270001`，再 `db push` 並重新比對 local／remote。
- 原則：事件 schema 變更要先套 migration，再發布會產生新事件的程式。

### GitHub push、Pages 與 Vercel 是三個不同發布面

- 症狀：GitHub main 與 Pages 已更新，但客戶正式站仍顯示舊 CTA。
- 原因：Pages workflow 成功不代表 Vercel 已建立新 deployment；本次 Git push
  沒有觸發 Vercel Git integration。
- 處理：查詢 Vercel deployments，確認只有 7 天前版本，再使用已連結專案的
  OIDC 正式部署並驗證 alias。
- 原則：分別確認 main SHA、Actions conclusion、Pages HTML 與 Vercel live HTML。

### Vercel OIDC token 不是一般 `--token`

- 症狀：把 `VERCEL_OIDC_TOKEN` 傳給 `--token` 會收到 token 格式錯誤。
- 原因：OIDC token 與 Vercel personal access token 的使用方式不同。
- 處理：只設定 `VERCEL_OIDC_TOKEN` 環境變數，不把 token 放進命令列或檔案。

### `gh` 與 GitHub App 權限不一致

- 症狀：`gh auth status` 顯示舊 token invalid；GitHub App 建立 PR 回傳 403，
  但 `git ls-remote` 與 `git push` 正常。
- 原因：Git CLI credential、GitHub CLI token 與 GitHub App integration 是三套
  不同憑證與權限。
- 處理：先推送發布分支，再重新抓取遠端 main，確認沒有其他更新後使用
  fast-forward 合併並推送 main。
- 原則：不可因其中一個工具可用，就假設其他 GitHub 表面也有相同權限。

### `.git` 寫入權限會阻擋 branch、stage 與 commit

- 症狀：建立 branch 或 `git add` 時出現 `.git/index.lock` permission denied。
- 處理：只對 Git 指令使用提升權限，且明確列出本次檔案，不使用 `git add .`。

### 找不到指定資源 permalink

- 症狀：四張不同資源卡原本都導向同一個 IG 首頁。
- 原因：尚未取得可以核實的單篇貼文連結。
- 處理：移除假深連結，改為「內容整理中」與不可點擊狀態。
- 原則：內容發布後才補 permalink；未知連結不能假裝已完成。

### 固定 CTA 容易和 Hero CTA 同畫面重複

- 症狀：手機首屏同時顯示兩個相同 CTA，壓縮內容空間。
- 處理：用 Intersection Observer 監看 Hero CTA 與表單，只有離開 Hero 且尚未
  進入表單時顯示固定列。

### 表單成功不等於預約成立

- 症狀：如果成功畫面直接寫「已預約」，使用者會誤認時段已確認。
- 處理：日期與時段只記錄偏好，文案明確說明仍由 Dino 後續確認。

### 測試不能污染正式名單

- 本機流程驗證攔截 `/api/analytics`，測試成功／失敗分支而不建立真實名單。
- Production 僅送空 JSON 驗證 API 回傳 400，不寫入客戶資料。

### Figma View seat 無法寫入驗證板

- Figma 連線可驗證身份，也能回傳新檔 URL，但帳號目前是 Starter View seat。
- 新舊檔的 metadata、capture 與 asset upload 都回傳 `INVALID_ARGUMENT`。
- 驗證板已保留為本機 PNG；取得可編輯 seat 後才能重新匯入。

### Figma 本機 capture 需要重新載入與外部連線

- 只改 hash 不會重新載入剛加入的 capture script。
- 沙箱瀏覽器可讀 localhost，但無法載入 Figma 外部 capture script。
- 正確流程是加入 script、以完整 capture hash 重新載入、使用可連線的瀏覽器，
  並用同一個 capture ID 持續 polling。
