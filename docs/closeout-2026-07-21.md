## 踩坑筆記

### 本機網址不是正式部署

- 現象：本機網站過一段時間或 Codex session 結束後無法開啟。
- 原因：`next dev` 與本機背景程序不是永久公開主機，登出、重開機或程序停止後就會中斷。
- 解法：客戶固定使用 Vercel Production；本機網址只供開發。

### Vercel 暫存磁碟不能保存名單

- 現象：本機 JSON 檔可寫入，但部署到 serverless 後不能當成可靠資料庫。
- 原因：Vercel 函式檔案系統不是持久化客戶資料儲存層。
- 解法：正式名單與事件改存 Supabase；Production 缺少 Supabase 設定時直接拒絕寫入。

### 機密環境變數不能進前端或 Git

- 現象：Supabase service role、後臺密碼與 session secret 都是高風險值。
- 原因：使用 `NEXT_PUBLIC_*` 或提交 `.env` 會讓機密暴露給瀏覽器或公開 repo。
- 解法：三個值只放 Vercel Production server-side environment；`.env*`、`.vercel`、`.data` 全部忽略，發布前再掃描一次。

### GitHub Pages 不能執行表單 API 與管理後臺

- 現象：Next.js 首頁可視覺化，但 `/api/analytics`、登入 Cookie 與 Supabase service role 需要伺服器 runtime。
- 原因：GitHub Pages 只提供靜態檔案，不能安全承載 Node API 或機密。
- 解法：Pages 只做公開轉址入口；客戶填表與管理後臺固定使用 Vercel。

### 部署成功訊息不等於客戶流程可用

- 現象：平台顯示 `READY`，仍可能有表單、Cookie、資料庫或響應式版面問題。
- 原因：單看 build 結果沒有覆蓋線上整合流程。
- 解法：直接測試 live URL 的 HTTP 200、表單寫入、未登入轉址、登入後名單、CSV、桌機與 390px 手機版；完成後精準刪除測試資料。

### 全頁截圖沒有觸發捲動動畫

- 現象：第一張全頁截圖中段看似大片空白。
- 原因：截圖工具沒有實際捲動，Intersection Observer 尚未觸發內容進場。
- 解法：Playwright 逐段捲動後再截圖，並分別以 1440px 與 390px 驗證無水平溢位。

### GitHub CLI token 失效

- 現象：`gh auth status` 回報既有 `shaino0807` token invalid。
- 原因：本機舊授權已失效，無法建立 repo、push、啟用 Pages 或查詢 Actions。
- 解法：使用 GitHub 官方網頁流程重新授權，不在對話或文件中傳遞 token；完成後再驗證 repo、Actions conclusion 與 live Pages URL。

### 首次 Pages workflow 比 Pages 啟用更早執行

- 現象：第一次 push 已觸發 workflow，但 `Configure Pages` 回報 Pages site `Not Found`。
- 原因：新 repo 的 push 先發生，Pages 的 `build_type=workflow` 設定稍後才建立。
- 解法：先用 GitHub API 啟用 Pages，再重新執行同一 workflow；run `29832616575` 最終 `success`，所有部署步驟完成。

### Actions 顯示 Node.js 20 deprecation annotation

- 現象：成功 workflow 仍顯示部分官方 actions 原本以 Node.js 20 為目標，目前由 runner 強制使用 Node.js 24。
- 影響：這次發布未失敗，屬於官方 action runtime 的提醒。
- 解法：目前保留已成功的官方 major versions；後續有新版時再升級並重新驗證，不為消除 annotation 降低 runner 安全設定。
